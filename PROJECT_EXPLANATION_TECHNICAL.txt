    - booking_reference
    - guest_name
    - guest_email
    - guest_phone
    - room_type_name
    - check_in_date

    - loadBookings(filters) - fetch and display bookings
    - filterBookings() - apply filters

    - viewBookingDetails(bookingId) - show modal with details
    - cancelBooking(bookingId, reason) - cancel with reason
    
    Update Booking Flow:
    1. Click edit icon
    2. Modal opens with current booking data
    3. Admin changes status dropdown
    4. If status = "confirmed", room dropdown appears
    5. Admin selects room to assign
    6. Submit triggers PATCH request to /php/api/bookings.php
    7. Request body:
       {
         "booking_id": 123,
         "status": "confirmed",
         "room_id": 5
       }
    8. Server updates booking
    9. If status changes to "confirmed", set confirmed_at timestamp
    10. If status changes to "cancelled", set cancelled_at timestamp
    11. Update room status if assigned
    12. Return success response
    13. Refresh bookings table
    
    Cancellation Flow:
    1. Click cancel button
    2. Modal prompts for cancellation reason
    3. Admin enters reason (required)
    4. Submit triggers PATCH request:
       {
         "booking_id": 123,
         "status": "cancelled",
         "cancellation_reason": "Guest requested refund"
       }
    5. Server updates booking with cancelled_at timestamp
    6. If room was assigned, change room status to "available"
    7. Send cancellation email to guest (optional)
    8. Refresh bookings table
    
    Pagination:
    - 50 bookings per page
    - JavaScript-based pagination (client-side)
    - Page navigation buttons
    
    Technical Features:
    - Real-time search with debouncing
    - Sortable columns (click header to sort)

    1. Click "Delete" button on room card
    2. System checks if room status is "occupied"

    6. System makes DELETE request to /php/api/rooms.php?id={room_id}

       - Room exists

    8. If validation passes, delete room
    9. Refresh rooms display

    - Occupied rooms: Status can be changed, but cannot be deleted
    - Rooms with active bookings: Cannot be deleted
    - Last room of a type: Warning before deletion

SQL Query Examples:
-------------------
1. Get all bookings with room type info:
SELECT b.*, rt.type_name, rt.base_price
FROM bookings b
JOIN room_types rt ON b.room_type_id = rt.room_type_id
ORDER BY b.created_at DESC

2. Get available rooms for a room type:
SELECT r.*
FROM rooms r
WHERE r.room_type_id = ? AND r.status = 'available'
AND r.room_id NOT IN (
  SELECT room_id FROM bookings
  WHERE room_id IS NOT NULL
  AND status IN ('confirmed', 'pending')
  AND check_out_date > CURDATE()
)

3. Get revenue for current month:
SELECT SUM(total_amount) as monthly_revenue
FROM bookings
WHERE MONTH(created_at) = MONTH(CURDATE())
AND YEAR(created_at) = YEAR(CURDATE())
AND payment_status = 'paid'

4. Get room occupancy rate:
SELECT 
  (SELECT COUNT(*) FROM rooms WHERE status = 'occupied') /
  (SELECT COUNT(*) FROM rooms) * 100 as occupancy_rate

TROUBLESHOOTING GUIDE
================================================================================

Common Issues:

1. 404 Error on API endpoints:
   - Check .htaccess file exists
   - Verify mod_rewrite is enabled
   - Check file paths are correct

2. Database connection failed:
   - Verify MySQL service is running
   - Check database credentials in config.php
   - Ensure database exists

3. Image upload not working:
   - Check images/room-types/ directory exists
   - Verify write permissions (755)
   - Check file size and type restrictions

4. Session timeout:
   - Increase session timeout in php.ini
   - Check session.gc_maxlifetime setting

5. CORS errors:
   - Verify CORS headers in api_helpers.php
   - Check browser console for specific error
